HMWK 3 — From the Caesar Cipher to Toy Elliptic-Curve Encryption

Encryption, decryption and attacks on restricted key spaces · Statistical cryptanalysis

Overview

This page compares two very different ciphers on the same message and then attacks both of them. The Caesar cipher is a classical symmetric cipher with only 26 keys. The toy elliptic-curve scheme is a public-key scheme (EC ElGamal) on the real secp256k1 curve, but its private key is restricted to a small range so that attacks can be run in a browser.

  1. Part A encrypts and decrypts a message with the toy elliptic-curve scheme.
  2. Part B does the same with the Caesar cipher.
  3. Part C compares the two schemes, including their statistical properties.
  4. Part D recovers the Caesar key from letter statistics and tests the attack on ciphertexts of different lengths.
  5. Part E attacks the restricted private key of the elliptic-curve scheme and explains why the same attack fails against a full-size key.

Note on the curve: in Homework 1 the curve y² = x³ + 7 was taken modulo 17 so that every point could be listed. Here, following the assignment, we use the real secp256k1 parameters (a 256-bit prime field) and make the private key small instead. The first choice makes the whole group tiny; the second keeps the group huge and only weakens the secret.

Part A — Toy elliptic-curve encryption (EC ElGamal)

The algorithm and the role of the keys

Public parameters. The curve secp256k1, y² = x³ + 7 over the prime field with p = 2256 − 232 − 977, the base point G, and the order n of G (a 256-bit prime).

  • Private key k (secret): an integer. In a proper scheme it is random in [1, n − 1]; in this toy scheme it is restricted to [1, 2b − 1] for a small b. Only its owner can decrypt.
  • Public key Q = kG (published): anyone can use it to encrypt. Recovering k from Q is the elliptic-curve discrete logarithm problem.
  • Ephemeral key r (secret, used once): a fresh random 256-bit number chosen by the sender for every character. It makes the encryption probabilistic.

Encoding. Each character of the message is turned into its code m (0 to 255) and then into the point M = mG.

Encryption of one character: choose a random r, compute R = rG and the shared secret S = rQ, then send the pair (R, C) with C = M + S.
Decryption: the receiver computes S = kR (which equals rQ, because kR = k(rG) = r(kG)), then M = C − S, and finally looks up m such that mG = M in a small table of 256 points.

Part B — The Caesar cipher

The Caesar cipher replaces every letter by the letter s positions later in the alphabet (cyclically), where the key s is a number from 0 to 25. Decryption shifts back by s. Case is preserved, and spaces, digits and punctuation are left unchanged. It is a symmetric cipher: the same key encrypts and decrypts.

Part C — Similarities and differences

Both schemes hide a message with a secret, both are deterministic functions of their inputs once all random choices are fixed, and both are reversed by an operation that mirrors the encryption (shift back, or subtract the shared secret). Everything else is different.

Measured statistical properties

The same sample of text is encrypted with both schemes. For the elliptic-curve scheme, the symbol of each character is the lowest byte of the x coordinate of C. The index of coincidence (IC) is the probability that two randomly chosen symbols are equal: about 0.065 for English letters (the sum of the squared published letter frequencies), 1/26 = 0.038 for uniformly random letters and 1/256 = 0.0039 for uniformly random bytes.

Part D — Statistical cryptanalysis of the Caesar cipher

A Caesar cipher only relabels the letters, so the ciphertext keeps the letter statistics of the language. The attacker needs a reference model of the language, estimated from a corpus, and then looks for the shift that makes the decrypted text look most like the language.

D.1 The corpus and the language model

The box contains a built-in English corpus written for this page. You can replace it with any larger text (a book, for example): the first 70 % is used to train the model and the last 30 % is kept aside as test text, so the attack is never tested on the text it learned from.

D.2 The attack methods

For every candidate key s from 0 to 25 the ciphertext is decrypted and scored. The best-scoring key is the guess.

  • Letter-frequency analysis (chi-square): compares the letter counts of the decrypted text with the counts expected from the corpus, χ² = Σ (Oi − Ei)² / Ei. The smallest value wins.
  • Most frequent letter: assumes that the most frequent ciphertext letter is the most frequent letter of the corpus (E). A one-line shortcut, but it uses only one number.
  • Bigram scoring (n-gram, n = 2): adds up the log-probabilities of all pairs of consecutive letters of the decrypted text, estimated from the corpus. The largest sum wins.
  • Exhaustive search with a dictionary: tries all 26 keys and counts how many common English words appear in each decryption. The most words wins. Spaces are ignored, so words are searched as substrings.

D.6 Effectiveness and limitations

  • Length matters. With only a handful of letters the statistics are too noisy and several keys look equally plausible; the success rate grows quickly as the ciphertext gets longer, and with a couple of hundred letters all good methods are almost always right.
  • Methods that use more information do better on short texts. Bigram scoring uses 26 × 26 numbers instead of 26, and the dictionary method uses word structure. The single-letter shortcut is the weakest.
  • The model must match the text. A corpus in another language, another style or with unusual vocabulary shifts the expected frequencies. A small corpus gives a noisy model: the single-letter shortcut suffers most, while chi-square and bigram scoring are more robust (see D.5).
  • Assumptions. The attack needs to know the language and to be sure that the cipher is a plain shift. Short ciphertexts, texts with unusual letter statistics (a text with no letter E, for example) and a wrong language all make it fail. With only 26 keys, an exhaustive search followed by a human reader would succeed anyway.

Part E — Attacking the restricted private key

The attacker knows the public parameters, the public key Q and the ciphertext. The private key is known to lie in [1, 2b − 1]. The goal is to find k, and then decrypt. Unlike the Caesar attack, nothing here depends on the statistics of the message: the attack works on the key pair alone and gives a certain answer, not a probable one.

  • Exhaustive search: compute G, 2G, 3G, ... by repeated addition of G and stop when kG = Q. It needs up to 2b − 1 point additions and almost no memory. (The page limits it to 222 steps.)
  • Baby-step giant-step (Shanks): write k = i·m + j with m = ⌈√2b⌉. Store the m “baby steps” jG in a table, then compute the “giant steps” Q − i·mG until one of them is in the table. It needs about 2√2b operations and a table of √2b points.

The attack uses the key pair currently shown in Part A (change the range there). The ciphertext is not needed to find k, but once k is known the message is decrypted.

E.2 A weakness of the scheme itself: reusing r

The restricted key is not the only problem. If the sender uses the same r for several characters, then Ci − C0 = (mi − m0)G, and since the differences mi − m0 are small numbers, they can be looked up in a table. The message is then known up to one unknown value m0 (256 possibilities): the scheme has degenerated into a shift cipher on byte values, like the Caesar cipher, and the same statistical idea finishes the job. No private key is needed. Tick “Reuse the same ephemeral r” in Part A, encrypt, and press the button. With fresh randomness the attack fails.

Discussion

Statistical attack on Caesar versus the key-space attack on the toy ECC scheme

  • What is exploited. The Caesar attack exploits a property of the plaintext and ciphertext: the letter statistics survive encryption. The ECC attack exploits only the size of the key space and the public key; the ciphertext and the language of the message are irrelevant.
  • Certainty. The Caesar attack is probabilistic and can fail on short texts. The ECC attack is deterministic: it always finds k, given enough computation.
  • Data needed. The Caesar attack needs enough ciphertext and a corpus of the right language. The ECC attack needs a single public key.
  • Cost. Caesar costs 26 trials at any length. The ECC cost grows with the key space: 2b additions by exhaustive search, about 2b/2 with baby-step giant-step.
  • Defence. Caesar cannot be repaired by statistics-resistant design while the key space is 26. The ECC scheme is repaired simply by using a full-size key.

Why this would not work against a properly configured ECC scheme

A proper private key is uniform in [1, n − 1] with n ≈ 2256. Exhaustive search would need about 2255 additions. Baby-step giant-step needs about 2129 operations and a table of 2128 points, which is impossible in time and in memory. The best generic attacks, such as Pollard’s rho, need about √n ≈ 2128 steps, and no significantly better generic attack is publicly known for secp256k1. This is also why the table above gives absurd times for 128 and 256 bits. Security comes from the size of the key space together with the hardness of the discrete logarithm, not from the secrecy of the algorithm.
