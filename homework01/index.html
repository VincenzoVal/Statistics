PRIVATE KEY → PUBLIC KEY in Ethereum, shown on a toy elliptic curve

Background

Elliptic-curve scalar multiplication can be viewed as a cryptographic one-way function. It is deterministic and easy to compute in the forward direction: private key k → public key Q = kG, where G is a fixed base point of the curve. Recovering k from Q is computationally hard. This is the Elliptic Curve Discrete Logarithm Problem (ECDLP).

Ethereum uses the curve secp256k1: y² = x³ + 7 over a prime field with p = 2256 − 232 − 977. An Ethereum address is then derived from the public key by hashing it with Keccak-256 and keeping the last 20 bytes.

This page uses a toy curve, y² = x³ + 7 (mod 17), so that every step can be followed by hand. The goal is to understand the basic idea of scalar multiplication, not to implement a real cryptographic system.

2. Repeated addition: G, 2G, 3G, ..., kG

Starting from G, we add G again and again using the elliptic-curve addition rule (chord-and-tangent formulas, computed modulo 17). When the two points are equal the formula for point doubling is used. If a sum has the same x but opposite y, the result is the point at infinity O, the neutral element of the group.

3. A faster method: double-and-add

Repeated addition needs k − 1 additions, which is hopeless for a 256-bit k. Double-and-add reads the binary digits of k from the most significant bit to the least significant one: for every bit the running point R is doubled, and if the bit is 1, G is added as well. This needs only about 2 · log2(k) operations.

5.7 Discussion

Properties that matter for a one-way function such as k → kG

  • Determinism and easy forward computation: the same k always gives the same Q, and double-and-add computes it quickly.
  • Hardness of inversion (ECDLP): given Q and G it must be infeasible to find k. In this toy example the brute-force button needs at most n attempts, where n is the order of G; for secp256k1 n is about 2256.
  • Roughly uniform output for uniform input: if k is chosen uniformly, Q is spread uniformly over the group generated by G. The frequency table shows this: the counts differ by at most one. Uniformity is necessary but it is not enough for security.

Properties specific to cryptographic hash functions

  • Avalanche effect: flipping one input bit should change about half of the output bits unpredictably. Scalar multiplication does not aim for this.
  • No algebraic structure: a hash should have no usable relation between outputs. Here (a + b)G = aG + bG and (k + 1)G = kG + G always hold, so Q + G is the public key of k + 1. This homomorphic structure is exactly what makes signatures and key exchange possible, and exactly what a hash must not have.
  • Arbitrary-length input, fixed-size output, collision resistance: a hash compresses any message into a short digest, so collisions exist and must be hard to find. For k between 1 and n − 1 the map k → kG is injective: collisions appear only when k wraps around modulo n, as the K > n experiment shows.
  • Statistical independence of input and output: a hash should show no correlation between input and output. Small correlations in the toy experiment come from the tiny group and from the fixed cyclic order of the multiples, not from a design goal.

In short: determinism, one-wayness and (for random k) uniformity are meaningful for the elliptic-curve one-way function, whereas avalanche, absence of algebraic relations and collision resistance over arbitrary inputs are properties specifically associated with cryptographic hash functions. This is also why Ethereum applies a hash (Keccak-256) to the public key to obtain an address.
